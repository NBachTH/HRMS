1.1 · Kiến Trúc Hệ Thống — Monolithic Modular

Dự án xây dựng theo kiến trúc Monolithic Modular — tổ chức code theo các module nghiệp vụ độc lập (Employee, Attendance, Payroll, Leave, Department, Auth) nhưng triển khai như một ứng dụng duy nhất. Phù hợp với quy mô team nhỏ, dễ phát triển, debug và deploy. Thiết kế hướng tới khả năng migrate sang Microservices trong giai đoạn phát triển tiếp theo.

Hệ thống tổ chức theo 4 tầng: Presentation Layer (Next.js) → API Layer (Spring Boot REST) → Business Logic Layer (Service classes theo module) → Data Layer (PostgreSQL + Redis).

1.2 · Công Nghệ Back-end
  • Ngôn ngữ & Framework: Java 21 LTS, Spring Boot 3.3.x (Spring Framework 6.x)
  • Cơ sở dữ liệu: PostgreSQL 15 (lưu trữ chính), Redis 7 (cache & session)
  • Bảo mật: Spring Security 6, JWT (Access Token 15 phút + Refresh Token 7 ngày), BCrypt password hashing
  • Database migration: Flyway — quản lý version schema
  • API Documentation: SpringDoc OpenAPI — Swagger UI
1.3 · Công Nghệ Front-end
  • Framework: Next.js 15 (App Router), React 19
  • Ngôn ngữ: TypeScript — type-safe API integration
  • Styling: Tailwind CSS 4, Lucide Icons, Recharts
  • HTTP Client: Axios — interceptor tự động refresh token
  • State Management: TanStack Query — server state, caching

// Request Flow — Xin Nghỉ Phép
1. Employee submit form → Next.js
2. POST /api/v1/leaves
   └─ Axios + JWT token (auto-attach)

3. Spring Security filter:
   └─ Validate JWT → extract roles

4. LeaveController → LeaveService
   ├─ Validate: đủ số ngày phép?
   ├─ Save LeaveRequest (PENDING)
   └─ Send email → Manager

5. Manager duyệt:
   PUT /api/v1/leaves/{id}/approve
   ├─ Update status → APPROVED
   ├─ Deduct leave balance
   └─ Notify Employee via email

6. Response ApiResponse<LeaveDTO>
   └─ TanStack Query invalidate cache
      → UI tự động refresh
🔐 JWT Security Flow

Login → Server tạo Access Token (15 phút) + Refresh Token (7 ngày), lưu cả hai trong HttpOnly Cookie (chống XSS). Khi Access Token hết hạn, Axios interceptor tự động gọi /auth/refresh — user không bị đăng xuất đột ngột. Logout ghi Refresh Token vào Redis blacklist — revoke tức thì, không thể dùng lại.

🏭 Tích Hợp Máy Chấm Công Vật Lý — Thiết Kế

Luồng: Máy chấm công (ZKTeco/RFID/Fingerprint) → HTTP POST đến /api/v1/devices/punch → AttendanceService xử lý raw log → ghép cặp CHECK_IN/CHECK_OUT → tính giờ làm, OT → lưu daily_attendance → đồng bộ Payroll khi tính lương tháng.

Device Simulator: Script Java/Python giả lập máy chấm công, tự động gửi HTTP POST theo kịch bản test (đi đúng giờ, đi trễ, quên check-out, ca đêm). Dùng để test và demo mà không cần phần cứng thật. Đây cũng là điểm kỹ thuật giúp trả lời câu hỏi hội đồng về kiểm thử tích hợp.

Thiết Kế CSDL & API

Schema các bảng quan trọng, quan hệ dữ liệu và API conventions

📐 Nguyên Tắc Thiết Kế Database

Chuẩn hóa 3NF. UUID làm primary key. Soft delete (deleted_at) thay hard delete để giữ audit trail. Optimistic locking (version column) cho bảng lương tránh concurrent update. Tất cả bảng có created_at, updated_at, created_by cho truy vết thay đổi.

// Bảng nhân viên & hợp đồng
CREATE TABLE employees (
  id            UUID PRIMARY KEY,
  employee_code VARCHAR(20) UNIQUE,
  full_name     VARCHAR(200) NOT NULL,
  email         VARCHAR(100) UNIQUE NOT NULL,
  department_id UUID REFERENCES departments(id),
  position      VARCHAR(100),
  level         VARCHAR(20), -- JUNIOR/MID/SENIOR/LEAD
  hire_date     DATE NOT NULL,
  status        VARCHAR(20) DEFAULT 'ACTIVE',
  created_at    TIMESTAMPTZ DEFAULT NOW(),
  deleted_at    TIMESTAMPTZ,   -- Soft delete
  version       BIGINT DEFAULT 0  -- Optimistic lock
);

CREATE TABLE contracts (
  id            UUID PRIMARY KEY,
  employee_id   UUID REFERENCES employees(id),
  type          VARCHAR(30), -- PROBATION/FULLTIME
  start_date    DATE NOT NULL,
  end_date      DATE,         -- NULL = không xác định
  base_salary   DECIMAL(15,2) NOT NULL,
  status        VARCHAR(20)  -- ACTIVE/EXPIRED
);
// Bảng chấm công (raw log + xử lý)
-- Raw log từ máy chấm công (append-only)
CREATE TABLE attendance_logs (
  id          UUID PRIMARY KEY,
  employee_id UUID REFERENCES employees(id),
  device_id   UUID REFERENCES devices(id),
  punch_time  TIMESTAMPTZ NOT NULL,
  punch_type  VARCHAR(20), -- CHECK_IN/CHECK_OUT
  raw_data    JSONB         -- Dữ liệu thô từ thiết bị
);

-- Kết quả đã xử lý (tính giờ làm)
CREATE TABLE daily_attendance (
  id             UUID PRIMARY KEY,
  employee_id    UUID,
  work_date      DATE,
  check_in_time  TIMESTAMPTZ,
  check_out_time TIMESTAMPTZ,
  hours_worked   DECIMAL(4,2),
  ot_hours       DECIMAL(4,2),
  status         VARCHAR(20),
  -- PRESENT/ABSENT/LATE/HALF_DAY/FORGOT_CHECKOUT
  UNIQUE (employee_id, work_date)
);
// Bảng lương (payroll records)
CREATE TABLE payroll_records (
  id           UUID PRIMARY KEY,
  employee_id  UUID REFERENCES employees(id),
  period       VARCHAR(7) NOT NULL, -- '2024-09'
  base_salary  DECIMAL(15,2),
  allowances   DECIMAL(15,2),  -- Tổng phụ cấp
  ot_pay       DECIMAL(15,2),  -- Lương OT
  bonus        DECIMAL(15,2),  -- Thưởng KPI
  bhxh_deduct  DECIMAL(15,2),  -- 8% BHXH
  bhyt_deduct  DECIMAL(15,2),  -- 1.5% BHYT
  bhtn_deduct  DECIMAL(15,2),  -- 1% BHTN
  pit_deduct   DECIMAL(15,2),  -- Thuế TNCN
  net_salary   DECIMAL(15,2),  -- Thực lĩnh
  status       VARCHAR(20),
  -- DRAFT → CONFIRMED → PAID
  UNIQUE (employee_id, period)  -- 1 record/tháng
);
